# Image Organizer — 功能介绍

> 本文从用户视角列出所有功能，每项都说明：**做什么 / 怎么用 / 什么场景需要 / 实际效果**。
> 想看内部如何实现请看 `项目技术分析文档.md`，想看快速上手请看 `README.md`。

---

## 1. 按拍摄时间归档（核心功能）

**做什么**：把源目录里所有照片视频按"年/月"两级目录归档到目标目录。

**怎么用**：
```bash
python organizer.py --source <源> --target <目标> --duplicates <重复目录>
```

**时间从哪来**（4 级降级，自动选最权威的）：

| 优先级 | 来源 | 标签 | 适用 |
|------|------|------|------|
| 1 | 缓存命中（来自 ExifTool 预热） | `exiftool-cache` | 多数文件 |
| 2 | ExifTool 单文件查询 | `exiftool` | 缓存未命中 |
| 3 | Pillow 读 EXIF | `pillow` | 没装 ExifTool 时 |
| 4 | 文件修改时间 (mtime) | `mtime` | 前面都失败 |

**实际效果**：
```
输入:  D:/AHAHA/DCIM/Input_Photos/IMG_1234.HEIC (拍摄于 2024-03-15)
输出:  D:/AHAHA/DCIM/Organized_Photos/2024/03/IMG_1234.HEIC
```

**为什么不按"年-月-日"或"年/月/日"**：照片量大时按月分文件夹够用，按日会产生上千个零散文件夹。需要更细可改 `_process_group` 里 `target_dir` 那一行。

## 2. 字节级去重（默认开启）

**做什么**：内容字节完全相同的文件，第二份开始自动移到 `duplicates/` 目录而不是归档目录。

**怎么用**：默认开启，无需参数。

**算法**：
1. 先看文件大小（size）
2. size 唯一的文件直接放行（照片几乎不可能 size 完全相同而内容不同）
3. 只对 size 重复的文件算 MD5 比对

**实际效果**：
```
输入: IMG_5678.JPG (100KB)
      IMG_5678_dup.JPG (100KB, 内容相同)
输出: 2024/03/IMG_5678.JPG       (归档)
      duplicates/IMG_5678_dup.JPG (识别为重复)
```

**性能**：5000 张照片中如果 80% size 唯一，会跳过 80% 的 MD5 计算（IO 节省最大）。

**典型场景**：iPhone 多次"导入到电脑"积累的副本、相同照片被反复拷贝多次。

## 3. 视觉去重（可选，需要 `--phash`）

**做什么**：识别"同一张图但不同压缩/分辨率"的视觉相似版本。字节去重抓不到这种（因为 size 不同），需要感知哈希。

**怎么用**：
```bash
python organizer.py ... --phash --phash-threshold 4
```

- `--phash`：启用
- `--phash-threshold N`：汉明距离阈值（默认 4），越小越严格；0 = 完全相同的 phash，4-6 = 视觉极相似

**前置依赖**：`pip install imagehash`（没装会报错并退出）。

**算法**：
1. 用 perceptual hash (pHash) 算每张图的 64-bit "视觉指纹"
2. BK-tree 索引（O(log N) 查询）找近邻
3. 距离 ≤ threshold 视为视觉重复，进 `duplicates/`

**实际效果**：
```
输入: photo.jpg (原图, 5MB)
      photo_compressed.jpg (压缩版, 800KB, 同一张照片)
输出: 2024/03/photo.jpg              (归档, phash 入库)
      duplicates/photo_compressed.jpg (距离 0, 识别为视觉重复)
日志: pHash 视觉重复 (dist=0): photo_compressed.jpg ≈ ...tgt/2024/03/photo.jpg
```

**典型场景**：微信 / iMessage 压缩版与原图共存；从邮件下载的低质量副本。

**已知限制**：pHash 不区分颜色（DCT 后只看亮度结构），所以纯色图（200×200 全红 vs 全蓝）会被误判为相同。复杂照片基本不会误判。

## 4. Live Photo 配对

**做什么**：iPhone 实况照片由 `IMG_xxxx.HEIC` (主图) + `IMG_xxxx.MOV` (实况视频) 组成。本工具识别同名 HEIC + MOV 为一组，**用主图的时间归档到同一目录**，保留 iPhone 重新导入时的关联。

**怎么用**：默认开启，无需参数。

**为什么重要**：HEIC 主图和 MOV 实况视频的 EXIF 时间常常差几秒（拍照瞬间有先后），独立按时间归档可能跨月份分到不同目录，破坏 Live Photo 关联。

**实际效果**：
```
输入: IMG_1234.HEIC (EXIF: 2024-02-29 23:59:58)
      IMG_1234.MOV  (CreateDate: 2024-03-01 00:00:01)
输出: 2024/02/IMG_1234.HEIC  ← 用 HEIC 时间决定目录
      2024/02/IMG_1234.MOV   ← MOV 跟随，不独立按 03 月归档
```

**primary 选取规则**（同名多文件时谁决定目录）：
- 图片 (HEIC/JPG/PNG/...) > 视频 (MOV/MP4/...) > sidecar (AAE)
- 同优先级取首个

## 5. AAE sidecar 跟随 + IMG_E 编辑变体识别

**做什么**：iPhone 照片编辑后会生成两类附属文件：

| 文件 | 含义 |
|------|------|
| `IMG_1234.AAE` | 编辑参数（裁剪、滤镜等的元数据） |
| `IMG_E1234.JPG/HEIC/AAE` | "E" 前缀 = edited，编辑后的导出版 |

本工具把这些都识别为 `IMG_1234` 原图的伴随文件，归到同一目录。

**怎么用**：默认开启。

**关键归一化**：`IMG_E1234` → `IMG_1234`（前缀去掉），所有 stem 相同的文件聚成一组。

**实际效果**：
```
输入: IMG_1234.HEIC      (原图)
      IMG_1234.MOV       (Live Photo 视频)
      IMG_E1234.JPG      (编辑后导出)
      IMG_E1234.AAE      (编辑参数)
输出: 全部归档到 2024/03/ 同一目录
```

**为什么必须**：默认按文件名匹配，`IMG_E1234.AAE` 与 `IMG_1234.HEIC` stem 不同，会被当成独立文件单独归档（按 AAE 自身的时间戳分到错误月份），破坏编辑参数与原图的关联。

## 6. 跨盘原子移动（断电安全）

**做什么**：source 与 target 在不同硬盘时，用两阶段提交保证移动操作原子性，断电不留半成品。

**怎么用**：默认开启。同盘移动用 `os.replace`（操作系统原子）；跨盘自动切两阶段。

**为什么重要**：标准库 `shutil.move` 跨盘时退化成 copy + unlink，**非原子**。中途断电会留下"目标半成品 + 源完好"，下次扫描会再次"成功归档"源文件，造成永久残留。

**两阶段流程**（跨盘时）：
```
1. copy 到 target.partial
2. fsync 强制刷盘 (避免内容还在 page cache 时崩溃)
3. 原子 rename: target.partial → target
4. 删源文件
```

每个阶段失败都可恢复（详见技术分析文档 §5.2）。

**典型场景**：source 在 D 盘，target 在外置 E 盘或网络盘；笔记本电池没电、雷电断电。

## 7. 断点续跑（默认开启）

**做什么**：状态写入 `<target>/.organizer_state.json`，中途中断（Ctrl+C / 断电 / 关机）后下次启动自动跳过已处理文件。

**怎么用**：
- 默认开启
- 想从头跑：加 `--no-resume`
- 想清空状态从头：删除 `<target>/.organizer_state.json`

**状态内容**：
```json
{
  "version": 2,
  "size_hashes": {"123456": ["hash1", "hash2"], ...},   ← 跨次去重
  "processed_paths": ["D:/.../IMG_1234.HEIC", ...],     ← 跳过已处理
  "saved_at": "2026-05-10T15:54:03"
}
```

**何时存盘**：
- 每 30 秒一次（心跳同时存）
- 每组处理完成后
- Ctrl+C 时
- 正常退出时

**实际效果**：
```
第一次跑到 1500/5000 时 Ctrl+C
日志: 用户中断，状态已保存，可下次续跑

第二次启动同样命令
日志: 断点续跑: 已加载 X 个 size 桶 / Y 个历史哈希 / 1500 条历史路径
      跳过 1500 个已处理文件 (断点续跑)
```

**典型场景**：几千张照片要跑十几分钟，中途网络盘卡顿、Ctrl+C、电脑休眠都不会丢进度。

## 8. ExifTool 持久进程加速（自动）

**做什么**：调用 ExifTool 读取 EXIF 时不再每文件 fork 一次进程，而是常驻一个 ExifTool 进程通过 stdin/stdout 批量交互，省掉数千次冷启动开销。

**怎么用**：默认开启（只要检测到 ExifTool 可执行文件）。

**性能提升**：

| 文件数 | 旧实现 (每文件 fork) | 新实现 (持久进程) | 提速 |
|-------|---------------------|------------------|------|
| 1000 | 5-8 min | 30-60 sec | ~10x |
| 5000 | 25-40 min | 2-3 min | ~13x |
| 10000 | 50-80 min | 4-6 min | ~13x |

**ExifTool 部署**：从 [exiftool.org](https://exiftool.org/) 下载 Windows 版后任选：
1. 项目根：`./exiftool.exe` + `./exiftool_files/`（官方 zip 直接解压）
2. 子目录：`./exiftool/exiftool.exe`（手工放置）

**容错**：daemon 崩溃自动重启（最多 3 次），超限后整体降级到 Pillow / mtime，不影响主流程。

**没装 ExifTool 怎么办**：自动跳过，全部走 Pillow → mtime。HEIC/视频时间会读不到（Pillow 不支持），但主流程仍能完成。

## 9. 并发 MD5（IO 加速）

**做什么**：MD5 哈希计算用线程池并发，IO 密集场景能跑满磁盘吞吐。

**怎么用**：
```bash
python organizer.py ... --workers 8
```
默认 4 worker，IO 强的可以拉到 8-16。

**适用场景**：固态硬盘 + 大量待哈希文件（即 size 桶撞了很多）。

**实际效果**：1000 个 size 重复的文件 MD5 计算，4 worker 比单线程快约 2-4x（取决于磁盘）。

## 10. Dry-run 预演（决策前必备）

**做什么**：完整跑一遍流程但不实际移动文件，只打印"会做什么"。

**怎么用**：
```bash
python organizer.py ... --dry-run
```

**输出示例**：
```
[DRY-RUN] D:/.../IMG_1234.HEIC -> D:/.../tgt/2024/03/IMG_1234.HEIC
[DRY-RUN] D:/.../IMG_5678.JPG -> D:/.../dup/IMG_5678.JPG
```

**典型场景**：第一次对一个新目录跑之前先 dry-run 看一眼分配是否合理；调整 `--phash-threshold` 后看视觉去重激进程度。

**注意**：dry-run **不会写状态文件**，所以多次 dry-run 不会污染断点续跑数据。

---

## 11. 单点失败隔离

**做什么**：单个文件失败不会让整个批量任务挂掉。失败收集起来，末尾统一打印失败清单。

**怎么用**：默认开启。

**失败分两类**：

| 类型 | 含义 | 退出码 |
|------|------|-------|
| `FAIL` | 业务失败（如完全读不到时间） | 1 |
| `ERROR` | 脚本异常（如 IO 错误、权限拒绝） | 2 |

**实际效果**：
```
处理完成
  扫描:       5000
  归档成功:   4998
  业务失败:   1
  脚本异常:   1

失败清单 (共 2 条):
  [FAIL] D:/.../damaged.heic -> 读取时间失败: ValueError: invalid date
  [ERROR] D:/.../locked.jpg -> stat 失败: PermissionError: ...
```

## 12. 心跳进度（长跑可视）

**做什么**：每 30 秒打印一次 `心跳 X/Y (百分比)`，避免长跑时不知道是在卡住还是在跑。

**怎么用**：默认开启，间隔写死 30 秒（`HEARTBEAT_INTERVAL_SEC`）。

**实际效果**：
```
2026-05-10 15:54:03 | INFO | 心跳 1500/5000 (30.0%)
2026-05-10 15:54:33 | INFO | 心跳 2400/5000 (48.0%)
```

同时心跳触发状态盘存（断电最多丢 30 秒进度）。

---

## 13. 退出码语义（脚本集成）

**做什么**：用退出码表达运行结果，方便 PowerShell / batch 脚本判断。

| 退出码 | 含义 |
|-------|------|
| `0` | 全部成功 |
| `1` | 有业务失败（FAIL，例如个别文件读不到时间） |
| `2` | 有脚本异常（ERROR）或参数错误 |
| `130` | 用户 Ctrl+C 中断（状态已保存，可续跑） |

**典型用法**（PowerShell）：
```powershell
python organizer.py ...
if ($LASTEXITCODE -eq 0) { Write-Host "全部成功" }
elseif ($LASTEXITCODE -eq 130) { Write-Host "已中断，明天续跑" }
else { Write-Host "有失败，查看日志"; exit $LASTEXITCODE }
```

`run.bat` 已实现该模式。

## 14. 一键启动 (run.bat)

**做什么**：双击运行的 Windows 批处理，预设源/目标/重复目录路径，调用 organizer.py 并打印中文结果摘要。

**怎么用**：编辑 `run.bat` 顶部三个路径变量后双击。

**默认配置**：
```bat
set "SOURCE=D:\AHAHA\DCIM\Input_Photos"
set "TARGET=D:\AHAHA\DCIM\Organized_Photos"
set "DUPLICATES=D:\AHAHA\DCIM\Duplicates"
```
默认带 `--phash --workers 8`。

**适合人群**：不熟悉命令行的家庭用户、想固化常用配置的频繁使用者。

## 15. 完整 CLI 参数表

```
--source DIR              源目录（必填，待整理的照片所在）
--target DIR              目标目录（必填，按年/月归档到这里）
--duplicates DIR          重复文件目录（必填）
--exiftool PATH           exiftool.exe 路径（默认自动探测）
--dry-run                 只打印不移动（决策前预演）
--phash                   启用视觉去重（需 imagehash 库）
--phash-threshold INT     pHash 汉明距离阈值（默认 4）
--workers INT             并发 MD5 worker 数（默认 4）
--no-resume               禁用断点续跑（从头跑）
--log-level LEVEL         日志级别 DEBUG/INFO/WARNING/ERROR（默认 INFO）
```

## 适用场景速判

| 你的需求 | 推荐命令 |
|---------|---------|
| 第一次整理 iPhone 几千张照片 | `--phash --workers 8`（先 `--dry-run` 看一眼） |
| 只想重新整理，不想去重 | （不加 `--phash`，字节去重无法关闭） |
| 中断后续跑 | 重复同样命令即可（断点续跑默认开） |
| 网络盘 / 外置盘 慢 | `--workers 2` 降并发，避免 IO 阻塞 |
| 调试归档结果 | `--dry-run --log-level DEBUG` |
| 完全重新跑（清空状态） | `--no-resume`，或删 `<target>/.organizer_state.json` |
